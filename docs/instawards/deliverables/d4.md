## The failure matrix

The four failures the SOW names, with the behaviour the rail must show. All four pass in the injection suite. The worker, co-signer and database are real, and Horizon and the co-signer network hop are injected. The observed behaviour, the two defects #46 found and #47's co-signer fix are in the [payout failure matrix](https://github.com/artisam-centient/centient/blob/develop/docs/payout-failure-matrix.md).

| Failure | Must happen | Must never happen |
| --- | --- | --- |
| **Sequence collision** (two payouts race for the same sequence number) | One payout lands and the other retries on a fresh sequence | A second transfer for the same submission |
| **Co-signer outage** | The payout stays pending, an alert fires, and it resumes when the co-signer returns | A payout with one signature, or a status that says "paid" |
| **Daily cap exceeded** | Both signers refuse independently and an alert fires | Either signer alone lifting the cap |
| **Horizon timeout** (outcome unknown) | The payout stays reconcilable and is resolved only from on-chain proof | A blind resubmit, which is exactly how a double payment happens |

## Network

The sprint runs on **Stellar testnet only** (D-7). The code keeps its guard: `COSIGNER_ISOLATION_LEVEL=same-workspace` refuses to sign on `STELLAR_NETWORK=public`, so the deployed topology cannot pay out on mainnet even by misconfiguration.
