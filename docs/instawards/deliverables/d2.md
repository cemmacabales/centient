# D2 — Wallet-native onboarding

> **Statement of Work, Deliverable 2.** Replace email-and-password contributor access with wallet-native identity. A contributor proves ownership with a one-time signed challenge, gets a session keyed to their Stellar address, and has sponsored account and trustline setup without holding XLM. The same address is identity and payout destination, and sponsored reserves can be reclaimed safely. Full wording in the Statement of Work, §4.1; evidence in §6.1.

## What a contributor can do when this is done

Open [beta.centient.work](https://beta.centient.work) with the Freighter extension set to testnet and click **Connect**. Freighter asks them to sign a short message that proves they own the address. That is their sign-up and sign-in. If the wallet is brand-new, Centient creates the account and adds the USDC trustline; the contributor approves one signature and spends nothing. From then on, that address is where every reward goes.

## QA verdict

The gate passed by **owner acceptance, not a clean 40 of 40.** QA ran 28 cases. The developer ran 8 more that need keys or database access, with evidence for each. One case was re-baselined: the deployed build turned out stricter than the test's model (TC-023). One case cannot be reached in the build (TC-020).

Two cases were **never run in a browser**:

* **TC-005 step 3.3, wrong-account state.** Freighter itself stops a real account mismatch, so this can only be produced by forging the signer. The server half is proven: a proof for one address that names another as signer returns `401 wrong_signer` and no session. The on-screen message rests on its unit test.
* **TC-038, taking over an unused wallet account.** The server half is proven. The screen that follows rests on its unit test.

Both are accepted as a low-priority residual. Running them later would not reopen the gate.

After the tested SHA, `staging` moved only by a contact-email string change, which no D2 case checks. The pass carries over to it.

## Known limits

* **Phones.** Deliverable 2 signs in with the Freighter browser extension only. Decision D-4 (22 September) brought Freighter Mobile over WalletConnect v2 into Deliverable 3. → [D3](d3.md)
* **Wallet rotation** is out of scope (D-3). An account is bound to one wallet.
* **Logout** does not revoke the 7-day session token.
* **Most sponsored reserves stay outstanding.** They can only be revoked once the owner holds XLM, so they remain a tracked, capped liability.
* **Email accounts** can no longer register. An existing email account must claim a wallet before it can earn or withdraw.
